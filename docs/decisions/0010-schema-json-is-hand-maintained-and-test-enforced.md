# ADR-0010: `schema.json` is hand-maintained, and five tests hold it in place

- **Status:** Accepted
- **Date:** 2026-09

## Context

`packages/protocol/src/types.rs` is the source of truth for the wire protocol.
`packages/protocol/schema.json` is the published contract for non-Rust clients.
It was, at one point, generated by a script that **mutated the derived artifact
rather than the source** — and injected a **duplicate `Clipboard Request`
branch** into the `oneOf` array.

A duplicated `oneOf` branch makes the union ambiguous. A *valid*
`clipboard/request` message matched two branches, and a message that matches more
than one branch of a `oneOf` is an **error** for any conforming JSON Schema
validator. So the published schema **rejected valid traffic** — for Dart, for
TypeScript, for anyone validating against it. The duplicated branch was
referenced by nothing, and nothing in the build detected it.

The failure mode is distinctive: the schema was not too permissive, it was too
*strict*, in a way that only a real sample message could reveal. The only
symptom was a failing contract test that the generation script had been
interleaved with.

A second, near-invisible instance of the same class: `websocket.ts` once declared
`interface ClipboardRequestMessage` **twice**. TypeScript *merges* interface
declarations rather than reporting a duplicate, so `tsc` exited 0 while the
effective type was the union of the two declarations. A red build would have
been better than a green one that was quietly wrong.

## Decision

1. **`types.rs` is the single source of truth.** No script writes
   `schema.json`. It is hand-maintained, like the Rust types it describes.
2. **Five invariant tests hold it in place** (`packages/protocol/src/types.rs`,
   the `JSON Schema validation (schema.json vs serde types)` block at `:4472`):
   - `schema_oneof_branches_are_unambiguous` (`:4846`) — no two branches may
     share a `(type, action)` discriminator pair. This is the test that would
     have caught the duplicate. It checks the discriminator *pair*, not the
     title, because that is what actually makes two branches overlap.
   - `schema_oneof_branch_titles_are_unique` (`:4880`) — titles are the identity
     used to map schema branches onto Rust types and generated TypeScript
     interfaces.
   - `schema_sample_set_covers_every_oneof_branch` (`:4895`) — one representative
     sample per branch, with the sample-set size required to equal the branch
     count, so a new branch cannot be added without a sample.
   - `schema_accepts_every_sample_in_sample_set` (`:4915`) — every sample must
     validate. This is the round-trip that would have caught the schema
     rejecting its own protocol.
   - the sample-set round-trip against serde (`:3097`, `:3143`) — samples that
     survive a Rust round-trip must also satisfy the schema, and vice versa.
3. **The duplicate is removed.** `schema.json` has exactly one
   `Clipboard Request` branch (`:423`), and `websocket.ts` declares
   `ClipboardRequestMessage` once (`:107`).
4. **Codegen artifacts are frozen and must be regenerated, not edited.**
   `apps/desktop/src/types/websocket.ts:1-3` carries
   `// GENERATED FILE - DO NOT EDIT` and names its generator. A hand-edit there
   is invisible to `tsc` in the duplicate-declaration case and is lost on the
   next generation run.
5. **CI must `git diff --exit-code` after generation.** A generated artifact
   that differs from what is committed means either a stale artifact or a
   hand-edit, and both are failures. **This CI step now exists** — the `codegen`
   job in `.github/workflows/ci.yml` (added in `eed58bd`) runs it, covering
   `websocket.ts`, `protocol.dart` and `schema.json`. It is the natural
   home for the nested-lockfile check from
   [ADR-0001](0001-single-cargo-lockfile-and-workspace-dependencies.md) too —
   that one is also implemented, as the `hygiene` job's "Exactly one
   Cargo.lock" step.

## Consequences

**Easier.** Adding a message type now fails in a specific, named way: either the
sample set does not match the branch count, or the new sample is rejected, or the
sample does not round-trip through serde. Three of those are impossible to
satisfy by accident. The duplicate-branch class of bug is now caught by a test
whose failure message names both branches and their discriminators.

**Unwelcome.** Hand-maintained means duplicated knowledge. `types.rs` and
`schema.json` describe the same protocol twice, and nothing generates the second
from the first. The five tests reduce the risk; they do not remove the
duplication, and a change that satisfies all five is still a manual change
someone had to remember to make in two files.

**Unwelcome.** The invariant tests are Rust tests in the protocol crate, so
`schema.json` is only validated when that crate's tests run. There is no
standalone validator a non-Rust contributor can run without a Rust toolchain —
which is a barrier for exactly the people most likely to hand-edit the JSON.

**Unwelcome.** `git diff --exit-code` after generation is specified but absent, so
today a stale or hand-edited generated artifact is not caught by CI. The
`DO NOT EDIT` header is a comment, not a control.

**Unwelcome.** Interface merging means the "I declared it twice" bug has no
compiler signal at all. `tsc` exiting 0 is not evidence that a type is what you
wrote. A lint rule banning duplicate exported interfaces in generated files
would catch it; none is configured.

## Alternatives considered

**Generate `schema.json` from `types.rs` at build time.** Rejected: `schemars`
and its kin derive JSON Schema from Rust types, but they describe *structure*,
not the *discriminated union with per-branch const discriminators and titles*
that this protocol needs. A generated schema that did not reproduce the
discriminators would not be the contract the clients depend on. This is the same
reason the frontend settings type is compared rather than generated
(`commands/settings.rs:405-413`).

**Fix the generation script to insert before the last `]` so it cannot duplicate
a branch, and keep generating.** Rejected: it treats the symptom. The script's
error was writing to a derived artifact; a correct script on a wrong pipeline is
still a pipeline that can be wrong. And a script that mutates
`schema.json` in place makes the file's git history a mix of human and machine
edits, which is how the duplicate became invisible in review.

**Add a `Clipboard Request` sample only.** Rejected: a sample proves the branch
accepts a valid message. It does not prove no *other* branch also accepts it. The
ambiguity test is the one that catches the actual defect.

**Assert only that titles are unique.** Rejected: titles are a human label. Two
branches with distinct titles and the same discriminators are exactly as ambiguous
as two identically-titled ones, and the duplicate is harder to spot.

**Delete `schema.json` and require clients to be generated from `types.rs`.**
Rejected: it removes the published contract that non-Rust clients consume, which
is the artifact's entire purpose.
